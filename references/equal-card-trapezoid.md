# 等大卡片 + 对称梯形（先判断条件，再动版式）

这是**有条件才可用**的版式，不是通用方案。条件不满足硬套，会出现斜边断裂、卡片失衡、内容塞不进去三类问题。默认版式仍是"等宽网格铺满"（见 `layout-tokens.md`）。

## 一、四条前置条件（全部满足才能用）

| # | 条件 | 为什么 |
| --- | --- | --- |
| 1 | **层数 ≥ 4，且各层卡片数单调递增**（1→2→3→4→5→6） | 行宽 = 卡数决定，只有递增才形成斜边；一旦回退（3→5→4），轮廓就断成锯齿 |
| 2 | **相邻层卡数差 ≤ 2，最好差 1** | 差 1 是等差梯，斜边平滑；跳号（1→3→6）会出现大台阶，看着像两张图拼的 |
| 3 | **内容量相当，能塞进同一尺寸卡**（标题 ≤ 12 字 + 副标题 ≤ 12 字） | 等大卡的前提是内容同构；某层需要三行说明就必须放弃等大 |
| 4 | **没有"必须突出某层"的需求** | 等大卡让所有卡片权重相同；主角层要单独做横幅，不能混进等大卡阵列 |

**不满足时的替代方案**：

- 卡数不递增 / 层数 ≤ 3 → 用等宽网格（每行铺满、卡宽自适应），即默认方案；
- 需要突出某层 → 该层单独做整行横幅（跨满），其余层等大卡；
- 内容量差异大 → 放弃等大卡，按 `layout-tokens.md` 的分行高方案。

## 二、几何算式（1920×1080 实测参数）

卡宽 `W`、卡间距 `g`、层徽章列宽 `B`、徽章与卡区间距 `b`、行内左右 padding `p×2`：

```
行宽 L(n) = n×W + (n-1)×g + B + b + 2p
```

实测：W=262、g=12、B=96、b=14、p=12

| 卡数 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| 行宽 | 396 | 670 | 944 | 1218 | 1492 | 1766 |

收尾横幅（N 应用）取 1644 + 96 + 14 + 24 = **1778**，比 6 卡行宽 12px → 成为全图最长，语义上"有限底座、无限应用"落在最宽处。

**关键校验**：内容区宽 = 1920 − 2×68（页面 padding）= 1784，最宽行 1778 只剩 6px 余量——必须精确算，不能估。

- 若 `L(max) > 内容区宽` → **先减卡宽 W**，绝不减字号；
- 若还剩很多空白（差值 > 60px）→ 说明卡数太少撑不起梯形，改回等宽网格。

## 三、实现要点

```css
.layers { display: flex; flex-direction: column; align-items: center; justify-content: center; gap: 14px; }
.layer  { display: flex; gap: 14px; padding: 5px 12px; border-radius: 18px; background: rgba(30,58,92,.045); }
.r1 { width: 396px; } .r2 { width: 670px; } /* … 每行写死 */
.card { width: 262px; height: 96px; flex: none; }  /* 必须 flex:none，用 flex:1 宽度会被拉平，梯形消失 */
.lt   { width: 96px; flex: none; }               /* 层徽章在行内左侧，随行居中 → 自然阶梯 */
```

- 行高全图统一（横幅另行），卡片等大才有"模块感"；
- 层徽章不再是一列固定对齐，而是**跟着每行走**，这正是金字塔的重心所在；
- 梯形两侧留出的米白空区是设计的一部分，不要用装饰填满。

## 四、字号层级铁律（与梯形配套，最易被破坏）

**同一层级必须同一字号。禁止为塞进卡片而缩小字号——放不下就折行。**

| 层级 | 1920 画布 | 1280（PPT 版） |
| --- | --- | --- |
| 页面标题 | 44 | 29 |
| 横幅标题（中心目标 / N 应用） | 22 | 15 |
| 卡片主标题 | 19 | 13 |
| 卡片副标题 | 13 | 8.7 |
| 层序号 | 32 | 21 |
| 层序号后缀（个/类/大/项） | 15 | 10 |
| 层名 | 16 | 11 |
| 参数胶囊 | 13.5 | 9 |

破坏层级最常见的写法——**给单行加字号覆盖**：

```css
/* ❌ 这会让"底座卡"标题比其他层小一档 */
.r6 .head b { font-size: 15px; }
.r6 .exp    { font-size: 10.5px; }
```

要压高度只调 `padding` / `margin`，字号一律不动。

**折行处理**：

```css
.head b { line-height: 1.25; text-wrap: balance; }  /* 不要 white-space: nowrap */
```

- 去掉 `nowrap`，放不下自然折行；
- `text-wrap: balance` 让两行断得均衡，避免"数据要素流通平 / 台"这类单字孤行。

改完估算是否会折行：`可用文字宽 = W − 2p − 插画宽 − gap − 竖条(宽+gap)`，`单行容纳字数 ≈ 可用宽 ÷ 字号`。临界（差 2–6px）优先把插画宽收 8–12px，或把卡宽加 8px，再不行就让它均衡折行。

## 五、插画尺寸：统一的是"占位框"不是"高度"

```css
.ptop .illus { width: 60px; height: 60px; object-fit: contain; flex: none; }
```

- ❌ 只统一高度（`height:68px; max-width:88px`）→ 方图和 2:1 横条图视觉大小差一倍，用户会提"插画尺寸应该一致"；
- ✅ 固定方框 + `object-fit: contain` → 所有插画占位完全相同；
- 代价：横长构图（管道、时间轴、保险箱这类 2:1 图）在方框里等比内缩后显得偏矮。这是方案固有特性，**提前告知用户**，或后续把那几张换成竖构图；不要靠放大它们破坏统一；
- 所有行、所有特殊卡（中心目标、N 横幅）用同一尺寸，不要写 `.r1 .illus { height: 66px }` 这种特例。

## 六、出图前 grep 自检

```bash
grep -n "font-size" 图.html      # 基础规则之外不应有行内字号覆盖
grep -n "nowrap"    图.html      # 卡片标题不应出现
grep -n "\.r[0-9] \.illus"       # 不应有单行插画尺寸覆盖
grep -n "<span>个\|<span>类\|<span>大\|<span>项" 图.html   # 层徽章后缀必须是 <small>
```

最后一条是真实事故：第 5 行层徽章误写 `<span>大</span>`（其他行是 `<small>`），后缀继承了 32px 序号字号，"5 大"比"1 个"大一圈。**等大卡 + 同构行最容易漏这种一处笔误**，改完必须逐行比对标签结构。

## 七、转 PPT 可编辑版（1280×720 = 图片 2/3）

所有数值按 2/3 换算，不要重新设计：

| 项 | 图片版 | PPT 版 |
| --- | --- | --- |
| 卡宽 × 高 | 262 × 96 | 175 × 64 |
| 卡间距 | 12 | 8 |
| 徽章列宽 / 间距 | 96 / 14 | 64 / 9 |
| 行 padding | 12 | 8 |
| 插画占位 | 60×60 | 40×40 |
| 行宽 1→6 卡 | 396/670/944/1218/1492/1766 | 264/447/630/813/996/1179 |
| N 横幅行宽 | 1778 | 1185 |

要点：

- 卡片写死 `width`（不要 flex:1），行 Box 写死 `width` 并 `alignItems: center`，梯形才会出现；
- 每个标题/副标题/胶囊都是独立 `Text`，保证文字可直接编辑；
- **要"纯可编辑单页"**：`slidep` 没有删页命令，用 `slidep create 新文件` + `slidep upsert-dsl --page-index 0` 重建，不要留着图片页；
- 核验实际渲染：`slidep screenshot x.pptx --page-index 0 --out /tmp/ck.png`（是 `--out`，不是 `--output`）；
- PPT 资源必须英文文件名，中文名会导致解析失败。

## 八、PPT 字号/行距/分隔符现行标准（2026-11-06 定稿，优先级最高）

第七节的 2/3 折算表已升级为整数磅标准，**新页一律按本节写，不再用第七节旧值**：

| 层级 | 磅值(pt) | DSL 写法(px) | 说明 |
| --- | --- | --- | --- |
| 页标题 | 21 | 28 | |
| 层名条 | 13 | 17.33 | 层名允许折行（层名条宽 74） |
| 卡标题 | 12 | 16 | 标题竖条 3×16 |
| 组名 | 9 | 12 | |
| 正文/副标 | 8 | 10.67 | 最小值，不许再小 |

- **行距一律 lineHeight: 1.2**（2026-11-05 用户定）。
- **词条分隔符一律「 / 」**，不用「·」。
- 字号只许在用户区间内取（卡标题 10–12 / 组名 8–10 / 正文 ≥8 / 层名 12–14，单位磅）；放不下先调几何（层高/gap/折行/分宽），禁止缩字号。
- **单页只放架构图的页面**（如结合图页）：删页眉 pill 与标题区，主体铺满；底座行横排行头只写名称不带副标。

## 九、小卡按内容分宽（flex 加权，替代等宽 flex:1）

同层小卡不再默认 `flex: 1` 等宽。按正文宽度估算加权：`全角字数×字号px + 半角×0.5×字号px + 分隔符宽`，长的组 flex 大（如 4.5）、纯组名的小（0.9）。层高按"组名行 + 正文最多行数"收紧，空白随之消除。lint 报某组 bottom+5 且加 flex 仍不过 = 内容本质需要两行 → 允许折行 + 加层高，不硬撑单行。
